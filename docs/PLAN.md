# 흑백 집중 런처 — 기획 초안 v0

- 대상 기기: 갤럭시 Z 폴드8 (One UI 9.0, Android 17 / API 37)
- 배포: 개인용 사이드로드 (Play 스토어 배포 안 함)
- 상태: 조사 완료, **사용자 결정 대기** (맨 아래 [결정 필요](#13-결정-필요-사항))

> 이 문서는 조사 세션 5개와 검증 워크플로 결과를 합친 것입니다. 확신도가 낮거나 실기기 확인이 필요한 항목은 **[확인 필요]** 로 표시했습니다.

---

## 1. 결론

**만들 수 있습니다.** 다만 런처 앱 하나만으로는 "검색으로만 실행"을 완전히 강제할 수 없습니다. 아래 세 가지를 한 APK에 넣어야 합니다.

1. **런처(홈 앱)**: 흑백 텍스트 UI, 검색, 루틴 버튼, 실행 종료.
2. **흑백 제어**: 처음 한 번 PC에서 adb로 권한을 주면, 앱이 시스템 전체 흑백을 켜고 끌 수 있습니다.
3. **게이트키퍼(접근성 서비스)**: 알림·최근 앱·엣지 패널처럼 런처를 거치지 않는 경로로 열린 앱을 감지해 되돌립니다.

설정 앱에서 기본 홈 변경, 접근성 끄기, 안전 모드 진입은 **막을 수 없고 막아서도 안 됩니다**(버그가 났을 때의 탈출구). 이 앱은 "완전한 감옥"이 아니라 **충동을 꺾는 마찰 장치**로 설계합니다.

## 2. 핵심 개념: 집중 세션

"실행 종료"를 누르기 전까지의 상태를 **집중 세션**이라고 부릅니다.

| 상태 | 화면 | 앱 실행 | 비고 |
|---|---|---|---|
| 세션 ON (기본) | 모든 디스플레이 흑백 | 검색 또는 루틴 버튼으로만 | 기본 상태, 부팅 시 자동 복귀 |
| 일시 해제 | 원래 색 | 자유 | 15/30/60분 뒤 자동으로 세션 ON |
| 완전 종료 | 원래 색 | 자유 | 24시간 숙려 후에만 가능 (선택 기능) |

원칙:
- **루틴은 제한을 강하게만 할 수 있습니다.** 루틴 버튼으로 흑백을 풀거나 차단을 해제할 수 없게 합니다. 그렇지 않으면 루틴이 충동 우회로가 됩니다.
- 세션을 OFF로 바꾸는 경로는 **실행 종료 흐름 하나뿐**입니다.

## 4. 구조

```
┌──────────────── 한 APK ────────────────┐
│ ① 런처 UI (HOME)                       │
│    시계·날짜·배터리 / 루틴 버튼 / 검색  │
│    커버·메인 레이아웃 분리              │
│ ② 세션 관리자                          │
│    흑백 ON/OFF, 상태 저장, 부팅 복구     │
│    흑백이 꺼지면 다시 켬(감시)          │
│ ③ 게이트키퍼 (접근성 서비스)            │
│    허용 티켓 없는 앱이 뜨면 홈으로       │
│ ④ 루틴 엔진                            │
│    단계 순차 실행, 권한 사전 점검        │
│ ⑤ 실행 종료 흐름                       │
│    대기 → 문장 입력 → 해제 시간 선택     │
└─────────────────────────────────────────┘
```

**허용 티켓 방식(게이트키퍼)**: 검색이나 루틴으로 앱을 열 때만 그 앱에 "티켓"을 발급합니다. 티켓 없는 앱이 어느 디스플레이에든 뜨면 홈으로 보내거나 "검색으로 열어 주세요" 화면을 띄웁니다. 이 한 가지 장치로 최근 앱, 알림 탭, 빅스비/제미나이, 엣지 패널, DeX 작업 표시줄을 모두 처리합니다. 짧게 화면이 번쩍이는 것은 피할 수 없습니다.

게이트키퍼 구현 주의점:
- 마지막에 뜬 앱 하나만 보지 않고, **모든 디스플레이의 모든 창**을 검사합니다(삼성 팝업 창·분할 화면·PiP·DeX 창으로 여러 앱이 동시에 보일 수 있음).
- '홈으로 보내기'는 현재 포커스된 화면에만 작동하므로, 다른 화면(DeX 등)에는 그 화면 위에 차단 오버레이를 띄웁니다.
- 런처 UI와 **별도 프로세스**로 돌리고, 배터리 최적화·'절전 앱'에서 제외합니다. 꺼지면 홈에 **'보호 꺼짐'** 을 크게 표시합니다.
- **보안 폴더·비공개 공간**은 자체 앱 목록이 있어 우회로가 됩니다. 쓰지 않거나, 게이트키퍼가 그 안의 창도 보는지 실기기에서 확인합니다.
- 삼성 작업 표시줄은 타사 런처에서 꺼지지만 설정에서 강제로 켤 수 있어 우회로가 됩니다. 게이트키퍼가 처리합니다.
- 앱을 강제 종료하면 접근성 서비스가 꺼진 채로 남습니다. 런처가 adb로 받은 권한으로 서비스를 다시 켜고, 이를 '종료 1회'로 기록합니다.
- 검색으로 연 앱이 다른 앱을 여는 경우(카톡 링크 → 브라우저, 결제·로그인 연동)는 티켓을 이어받게 합니다.
- **위험**: 일부 은행·인증 앱은 사이드로드된 접근성 앱이 켜져 있으면 실행을 거부할 수 있습니다. **가장 먼저 실기기에서 확인**합니다.

항상 허용: 시스템 UI, 키보드, 권한 대화상자, 전화(수신·발신), 긴급 SOS, 잠금화면 카메라, 알람, 그리고 사용자가 정한 허용 목록 앱.

## 5. 흑백 구현

**1순위: daltonizer 키 (AOSP 17 소스로 확인됨)**
- 시작 시 기존 값을 저장한 뒤 `accessibility_display_daltonizer=0`(단색)을 **먼저** 쓰고, 그다음 `accessibility_display_daltonizer_enabled=1`을 씁니다. 모드 키가 없으면 기본값이 12(색약 보정)라서 순서가 중요합니다.
- `WRITE_SECURE_SETTINGS`는 `adb shell pm grant <패키지> android.permission.WRITE_SECURE_SETTINGS`로 부여합니다. (`adb install -r -g`만으로 부여될 수도 있지만 [확인 필요].) 재부팅·앱 업데이트 후에도 유지되고, **앱을 삭제하면 사라집니다**(그래서 서명 키를 고정해 덮어쓰기 업데이트만 합니다).
- 이 권한은 설정 화면에서 회수할 수 없습니다. 그래서 모드 방식보다 충동 우회에 강하고, 이 방식을 1순위로 둡니다.
- **앱을 삭제해도 흑백 설정은 남습니다.** 삭제 전에 앱에서 흑백을 되돌리거나, 설정 > 접근성에서 직접 끕니다.
- 흑백 설정값은 시스템에 저장되므로 재부팅 후에도, 잠금화면·AOD·안전 모드에서도 흑백이 유지됩니다.
- 부작용: 흑백이 켜져 있는 동안 삼성 '화면 모드'·화이트 밸런스 설정이 잠길 수 있습니다(표시 문제일 뿐).
- 세션 중 사용자가 빠른 설정에서 흑백을 끄면 `ContentObserver`로 감지해 즉시 다시 켭니다.
- 실행 종료 시 저장해 둔 값으로 되돌립니다.

**2순위: 모드(방해금지) 흑백 효과** [확인 필요]
- Android 15+ 공개 API. adb 없이 방해금지 접근 권한만으로 가능합니다.
- 상태 표시줄에 '모드'로 보이고, 사용자가 빠른 설정이나 설정 > 모드에서 끄거나 흑백 효과만 뺄 수 있습니다. 그러면 앱의 변경이 무시되므로 감지해서 모드를 새로 만들어야 합니다. 운전 모드가 켜지면 흑백이 눌릴 수 있습니다.
- One UI 9에서 서드파티 앱의 이 효과를 반영하는지는 미확인입니다.

**항상: 런처 UI 자체 흑백** — 권한이 없어도 런처 화면은 흑백 텍스트로만 구성합니다.

참고: 흑백은 화면 표시에만 적용됩니다. 스크린샷·사진은 컬러로 저장됩니다.

## 6. 검색

- **초성 검색**: `ㅋㅋㅇ` → 카카오톡.
- 입력 중인 마지막 음절도 매칭합니다(예: `칵` → `카카…`).
- **별칭**: `카톡` → 카카오톡, `유튜브` → YouTube.
- **영문 자판으로 친 한글**도 찾습니다: `zkzkdhxhr` → 카카오톡. 패키지 이름(`kakao`)으로도 찾습니다.
- 구현: 자바 표준 유니코드 정규화(NFKD)로 자모를 분해해 비교합니다. 약 150줄, 외부 라이브러리 없음.
  - 겹모음(ㅘㅙㅚㅝㅞㅟㅢ)은 앱 이름과 검색어 양쪽에서 쪼개야 `전호`(전화 입력 중), `ghkaus`(화면) 같은 입력이 맞습니다.
  - 검색창은 자동 대문자·자동 수정·추천을 끕니다(첫 글자가 대문자가 되면 `Rk…`가 `ㄲ`로 바뀜).
  - 삼성 키보드와 Compose 입력창 사이에 알려진 문제가 있어, 실기기에서 먼저 시험하고 기존 EditText를 대안으로 둡니다.
- 순위: 정확 일치 > 접두 일치 > 단어 시작 > 초성 접두 > 부분 포함.
- **추천 기본값**
  - 검색창은 탭할 때만 키보드를 띄웁니다(자동 포커스는 습관적 사용을 부름).
  - 1글자부터 결과, 최대 5개.
  - "자주 쓰는 앱" 추천은 넣지 않습니다.
- **방해 앱 등급** (선택)
  - 숨김: 이름을 끝까지 정확히 입력해야만 결과에 나옴.
  - 마찰: 실행 전 10초 대기 + [열지 않기] 버튼. 같은 날 반복할수록 대기가 늘어남.

## 7. 루틴 버튼

**동작 목록**

| 등급 | 동작 | 필요 조건 |
|---|---|---|
| 권한 없음 | 앱 실행, 앱 바로가기 실행(카톡 특정 채팅방 등), 딥링크/URL, 지연, 손전등, 미디어 볼륨, 재생/일시정지/다음 곡, 알람·타이머 설정 | 없음 (기본 홈 앱이라 바로가기 실행 가능) |
| 권한 없음 (반자동) | Wi-Fi/인터넷/NFC 패널 열기, 블루투스 켜기 확인창, 문자·일정 작성 화면 열기 | 사용자가 한 번 탭해야 함 |
| 설정 토글 1회 | 방해금지(런처 전용 모드), 벨소리 모드 | 방해금지 접근 허용 |
| 설정 토글 1회 | 밝기, 화면 꺼짐 시간 | 시스템 설정 변경 허용 |
| Shizuku | Wi-Fi·비행기 모드·위치 자동 토글 | Shizuku 실행 중일 때만. 꺼져 있으면 패널 열기로 대신 |
| 연동 | Tasker 작업 실행 (끝날 때까지 기다릴 수 있음) | Tasker(유료) + 외부 접근 허용 |
| 선택 권한 | 특정 음악 앱 재생 제어, 분 단위 대기 | 알림 리스너 접근 / `USE_EXACT_ALARM` |
| 불가 | 삼성 모드 및 루틴 실행, 구글 어시스턴트 루틴, 문자 자동 발송 | 공개 API 없음 |

**실행 방식**
- 화면 없는 동작(방해금지·볼륨·밝기 등)을 먼저 실행하고, **앱을 여는 동작은 마지막에 하나**만 두는 것을 기본으로 합니다.
- 중간에 앱을 여러 개 여는 것:
  - **일반 앱 실행**은 AOSP상 가능합니다. 기본 홈 앱은 백그라운드 실행 제한의 예외입니다. 단, 실행 순간 기본 홈이어야 하고 모든 실행에 새 작업(`FLAG_ACTIVITY_NEW_TASK`)을 붙여야 합니다. 삼성에서는 [확인 필요].
  - **바로가기(카톡 채팅방 등)·위젯 실행**은 다른 앱 이름으로 실행되므로 이 예외가 적용되지 않습니다. 다른 앱이 앞에 떠 있으면 막힙니다. 그래서 바로가기 단계 직전에 런처의 투명 화면을 잠깐 띄운 뒤 실행합니다.
- 루틴 실행을 유지하는 짧은 포그라운드 서비스는 **버튼을 누르는 순간** 시작합니다(중간에 시작하면 막힘). 진행 중인 단계 번호를 저장해 둡니다.
- 루틴을 시작하기 전에 기본 홈 앱 상태인지 확인합니다.
- 음악 재생목록 자동 재생은 앱마다 다릅니다. "딥링크로 열기 → 2~4초 대기 → 재생 키"를 기본으로 하고, 실기기에서 앱별로 확인합니다.
- 루틴 정의는 처음엔 JSON 파일(가져오기/내보내기), 편집 UI는 나중에 붙입니다.

```json
{
  "id": "commute", "label": "출근",
  "steps": [
    {"type": "dnd", "mode": "priority"},
    {"type": "volume", "stream": "music", "percent": 40},
    {"type": "deeplink", "uri": "spotify:playlist:XXXX", "package": "com.spotify.music"},
    {"type": "delay", "ms": 3000},
    {"type": "media", "action": "play"},
    {"type": "launch", "package": "com.nhn.android.nmap"}
  ]
}
```

## 8. 실행 종료 (마찰 설계)

**근거**: one sec 연구(PNAS 2023, 280명)에서 가장 효과가 큰 요소는 대기 시간이 아니라 **"그만두기" 선택지**였습니다. LocknType(CHI 2019)에서는 버튼 누르기만으로 13%, 30자리 입력으로 47.5%가 단념했습니다. TypeOut(CHI 2022)은 자기 다짐 문장 입력이 의미 없는 입력보다 효과가 컸습니다. 반대로 너무 강한 잠금은 사용자가 아예 꺼 버리고, 해제 후 원래대로 빠르게 돌아갑니다.

**추천 흐름**

1. **진입**: 홈 하단의 흐린 "종료" 글씨를 **3초 길게 누르기**.
2. **대기 화면**: 그날 첫 회 **60초**, 같은 날 다시 누를 때마다 **2배**(최대 10분), 자정에 초기화. 화면 중앙에 큰 **[돌아가기]** 버튼을 항상 표시. 화면을 벗어나면 대기가 처음부터 다시 시작됩니다.
3. **다짐 문장 입력**: 미리 직접 써 둔 문장(예: "지금 이걸 여는 건 피곤해서다")을 정확히 입력. 사유도 고릅니다(기록용).
4. **해제 시간 선택**: **15분(기본) / 30분 / 60분**. "무기한"은 없습니다.
5. **자동 복귀**: 시간이 끝나면 세션 ON. 1분 전에 알림.
6. **주간 한도**: 예) 주 3회. 넘으면 대기 시간이 더 길어집니다.
   - 빠른 설정에서 흑백을 끄거나 앱을 강제 종료하는 우회도 감지해 되돌리고 1회로 셉니다.
7. **설정 잠금**: 마찰을 약하게 바꾸는 설정 변경은 **24시간 뒤**에 적용됩니다.
8. **완전 종료**(선택): 24시간 숙려 → 생체 인증. 구글의 사이드로드 '고급 흐름'과 같은 방식입니다.
   - '일시 해제'는 런처 안의 해제 모드(흑백 끔, 앱 자유 실행)입니다.
   - '완전 종료'는 흑백을 되돌린 뒤 런처의 홈 등록 부분(activity-alias)을 스스로 꺼서 One UI 홈에 기본 홈 자리를 돌려줍니다. AOSP 소스로만 확인했고 삼성에서 [확인 필요]. 다시 켤 때는 기본 홈 지정을 새로 요청합니다.

**긴급 상황 안전장치**
- 긴급 전화·SOS는 OS가 항상 보장합니다(측면 버튼 5회).
- **허용 목록 앱**(전화, 문자, 지도, 택시, 결제, 은행, 인증/PASS, 카메라)은 검색에서 마찰 없이 바로 열립니다. 이걸로 실행 종료를 누를 일 자체를 줄입니다.
- 허용 목록에 없는 앱이 급히 필요하면 **"이 앱만 5분"**: 10초 대기, 하루 5회까지.

## 10. 설치·초기 설정 절차

1. 삼성 **자동 차단기** 잠시 끄기 (설정 → 보안 및 개인정보 보호 → 자동 차단기). 켜져 있으면 USB 명령과 사이드로드가 막힙니다.
   One UI 8.5+에는 '30분 뒤 자동으로 다시 켜기' 옵션이 있으니 설치 중에는 해제합니다.
2. PC에서 설치 스크립트 실행 (제가 만들어 드립니다):
   ```
   adb install -r -g launcher.apk
   adb shell pm grant <패키지> android.permission.WRITE_SECURE_SETTINGS   # 흑백 권한
   ```
   adb로 설치하면 '제한된 설정'이 걸리지 않을 것으로 봅니다(AOSP 기준). 걸리면 `adb shell cmd appops set <패키지> ACCESS_RESTRICTED_SETTINGS allow` 를 추가합니다 [확인 필요].
   **ADB 설치는 구글 개발자 인증 대상이 아닙니다**(2027년 한국 적용 이후에도 예외).
3. 앱 안의 설정 마법사로 나머지 권한 부여: 기본 홈 앱 지정 → 방해금지 접근 → 시스템 설정 변경 → 접근성 → 배터리 최적화·'절전 앱'에서 제외.
4. 자동 차단기 다시 켜기. **USB 디버깅도 끄기** — 켜 두면 PC로 모든 걸 풀 수 있는 상시 우회로가 됩니다. 업데이트할 때만 켭니다.
- 주의: Android 17 **고급 보호(Advanced Protection)** 를 켜면 접근성 권한이 회수되어 게이트키퍼가 꺼집니다.
- PC가 없을 때 대안: 무선 디버깅 + Shizuku로 2번 수행.
- 이 런처가 기본 홈이 아닐 때는 루틴의 앱 연속 실행과 바로가기 실행이 제한됩니다.

## 11. 기술 스택

| 항목 | 선택 |
|---|---|
| 언어/UI | Kotlin 2.4.20, Jetpack Compose (BOM 2026.09.00) + Compose 컴파일러 플러그인 |
| 빌드 | AGP 9.4.1 (Kotlin 내장, kotlin-android 플러그인 불필요), Gradle Wrapper 9.6+ (현재 9.8.1), JDK 21. 어노테이션 처리는 KSP (kapt 불가) |
| SDK | compileSdk / targetSdk 37, minSdk 35 (모드 흑백 API가 35부터) |
| 저장 | DataStore (설정·세션 상태), JSON 파일 (루틴) |
| 화면 구조 | 홈 액티비티(singleTask), 홈 등록은 activity-alias(완전 종료 시 끔), 설정은 비공개 별도 액티비티. 외부 화면용 홈을 넣는다면 singleTask가 아닌 별도 액티비티여야 함 |
| 권한 | `QUERY_ALL_PACKAGES` (앱 목록 전체 조회. 사이드로드라 정책 부담 없음), `WRITE_SECURE_SETTINGS`, `ACCESS_NOTIFICATION_POLICY`, `WRITE_SETTINGS`, 접근성 서비스 |
| CI | GitHub Actions: 서명된 release APK 빌드 → GitHub Release 첨부 (러너에 Android SDK 37 기본 설치됨). versionCode는 계속 증가(다운그레이드 설치 불가) |
| 서명 | 키스토어 1개 고정 (GitHub Secrets + 오프라인 백업). 잃어버리면 삭제 후 재설치 → adb 권한도 다시 부여해야 함 |

## 13. 실기기 확인 체크리스트 (코딩 전 30분, PC + adb)

- [ ] 삼성 흑백 토글을 켜고 끄면서 `adb shell settings list secure` 결과 비교 → 실제 키 확인
- [ ] `settings put secure accessibility_display_daltonizer 0` → `settings put secure accessibility_display_daltonizer_enabled 1` 후 커버·메인·유선 모니터(DeX)에서 흑백 확인 (스마트뷰·화면 녹화는 컬러로 나올 것으로 예상)
- [ ] `adb install -r -g`로 설치했을 때 흑백 권한이 자동으로 부여되는지 (`adb shell dumpsys package <패키지>`)
- [ ] 재부팅 후에도 흑백이 유지되는지
- [ ] F-Droid에서 Olauncher 등을 받아 기본 홈으로 지정 → 커버·메인 둘 다 뜨는지, 제스처·최근 앱·작업 표시줄 동작
- [ ] adb로 설치한 앱에 '제한된 설정'이 걸리는지, `appops` 명령으로 풀리는지
- [ ] 최근 앱 화면의 '추천 앱' 줄, 엣지 패널로 앱이 열리는지 (게이트키퍼가 막아야 할 경로)
- [ ] 자동 차단기가 켜진 상태에서 USB 디버깅이 막히는지
- [ ] **은행·인증 앱**이 접근성 앱(테스트용 아무 앱)이 켜진 상태에서도 실행되는지
- [ ] (시제품 단계) 런처가 뒤에 있을 때 앱을 연달아 열 수 있는지: `adb logcat | grep -i BAL`
